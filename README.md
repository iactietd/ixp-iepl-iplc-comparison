## 先说清楚：IXP专线服务商卖的"IX"，通常不是你想的那个IXP

按字面理解，IXP（Internet Exchange Point，互联网交换中心）是ISP、CDN、公有云这些网络互相对接的物理枢纽。企业自己"接入IXP"，指的是拿到一个交换中心端口，用自己的ASN和对等成员互联——这是重资产玩法，需要AS号、端口费和一堆BGP配置。

零售用户能在市场上买到的"IX专线"，实际上是另一回事。以MKCloud的IX产品为例，官方知识库的描述很明确：它是通过云厂内网接入的出海VPS，每台机器分配1个独立入口IP和1个独立出口IP。你从符合要求的云主机连进IX入口，VPS向境外发流量时从出口IP出去。交换中心的价值体现在上游——出口侧接入了Equinix IX、HKIX这类交换中心，以及对Google、Cloudflare等大厂的私有PNI互联，用户享受的是这条优化后的路由，而不是自己拥有IXP端口。

这个区别直接决定了两个使用边界，买之前必须知道：

- **出口方向单一**：IX的出口不支持外部连入，不能用来做公开网站、Webhook回调或游戏服务端。它是给"你主动去访问境外目标"这种场景准备的，比如运营后台、ERP、API调用。
- **入口有接入条件**：必须从支持的云厂网络连入。MKCloud目前深圳入口支持阿里云、腾讯云、百度云国内全网，以及火山云、华为云华南；上海入口支持阿里云、腾讯云、百度云国内全网，以及火山云、华为云、UCloud华东。不是随便一台BGP主机都能当前置，具体范围下单时以购物车说明为准。

另外提醒一句：标准IX产品默认没有SLA，对可用性有硬指标要求的，需要单独咨询付费定制。

## IX、IEPL、IPLC到底差在哪

这三类是跨境专线市场的主流形态，MKCloud三类都有在售。核心差异在于"你怎么接进去"和"线路形态"：

| 维度 | IX（上云互联） | IEPL | IPLC |
| --- | --- | --- | --- |
| 接入方式 | 必须通过云厂内网连入 | 独立入口IP直连 | 独立入口IP直连 |
| 线路性质 | 云厂优化网络，出口走BGP | 二层以太网专线 | 点对点物理专线 |
| 端内延迟参考 | 深港1~2ms | 广港约3ms | 沪日25ms上下、沪美124~134ms |
| 接入限制 | 绑定云厂网络，不限省份 | 入口可选八线BGP/电信/移动/联通等 | 类似IEPL |
| 典型用途 | 已有云上业务的出海访问 | 电商后台、Shopee等平台运营 | 对日、对美方向的API与传输 |

延迟数字来自官方页面和第三方测评，注意"端内延迟"只是入口到出口这一段，你全程体验的RTT还要加上境外目标站自身的距离，沪美方向134ms上下是物理距离决定的，换任何服务商都躲不掉。

一句话选型：业务跑在阿里云/腾讯云上、只做出向访问的，IX门槛最低；要独立入口、不依赖云前置的，看IEPL/IPLC；对日业务选沪日，对美选沪美。

## 值不值：基于已核验信息的几个判断

价格之外的证据，主要来自第三方测评和官方技术说明：

- **延迟表现**。多个独立测评给出的数字和官方口径基本一致：广港IEPL端内约3ms，晚高峰波动小；沪日IPLC约25ms；深港IX端内1~2ms。专线晚高峰掉速明显小于普通公网VPS，这也是它和"机场节点"最本质的区别——走的是运营商间专用通道，物理层面与公网隔离。
- **IP质量**。有测评用Scamalytics等工具检测，MKCloud的出口IP欺诈值为0，双端独立IP对做eBay、Shopee、TikTok这类对IP敏感的平台运营是实际加分项。注意官方也建议用固定IP直连方式访问，用域名连接方式会增加被阻断的风险。

- **稳定性风险**。商家成立时间不长，品牌知名度不如大厂，这是事实。测评圈的普遍建议是按月付起步，控制预付风险。另外官方公告里出现过"先锋版节点可能不稳定"的提示，新上的先锋线路购买前看清说明。
